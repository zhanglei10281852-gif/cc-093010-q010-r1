# 全球健康创新试点运营服务

这是一个面向健康科技展会、临床合作机构、康复机构和产业伙伴的 Python 后端。服务使用 FastAPI 与 SQLite 管理健康创新产品、试点场地、证据材料、公众体验反馈、参数化体验方案、排队场次、站点租约、失败恢复、观察记录版本和人工干预。所有运行状态保存在单个本地数据库文件中，不需要另行部署数据库、缓存、消息队列或浏览器界面。

## 已有能力

- 产品目录：登记来源国家、所属机构、产品类别、用途、风险级别与当前合规状态。
- 场地目录：维护展会体验点、医院、康复机构、研究机构和产业伙伴的能力与并发上限。
- 证据材料：按产品保存临床、性能、安全、合规和体验材料，使用内容摘要实现重复提交幂等，并支持接受或驳回。
- 体验反馈：按场地、场次引用和受众类型保存评分、标签、意见以及后续联系授权，重复反馈不会创建第二条记录。
- 体验方案：使用参数规则描述外骨骼、辅助诊断、数字疗法、慢病管理和数字中医等设备或服务的运行边界。
- 场次调度：提交方按项目和幂等键创建场次，执行站点按能力领取并获得有期限的租约。
- 执行回执：站点可以续租、提交观察记录或报告失败；可重试失败按照确定的退避时间重新排队。
- 失败恢复：租约到期后由恢复入口重新排队，达到最大尝试次数的场次转为失败。
- 人工干预：取消、人工重试、优先级调整和批量操作均保留操作者、原因、前后状态与批次标识。
- 队列冻结：按截止时点与产品、方案版本、场地类型、参与条件和质量规则生成不可变成员清单，逐条记录纳入或排除原因及当时的观察版本、证据状态；新版本以候选修订提出，签发前展示相对上一版的增加、移除与理由，签发后任何进程都无法改删。
- 队列导出：稳定成员顺序、去标识字段与内容摘要，同一请求幂等键重放返回同一制品，评审人员可凭摘要追到原场次和规则快照而看不到联系人信息。
- 身份审计：保留用户、角色、团队、会话、权限、审计事件和后台维护能力，敏感凭据只保存摘要。

## 运行环境

- Python 3.11
- SQLite 3，由 Python 标准库提供
- Linux、macOS 或 Windows

## 安装

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -e ".[dev]"
```

默认数据库位于 `./data/health-innovation.db`。可复制 `.env.example`，并通过 `HEALTH_INNOVATION_DATABASE_PATH` 指定其他本地文件。

## 数据库初始化与检查

```bash
python -m app.cli init-db
python -m app.cli check-db
python tools/verify_sqlite.py
```

## 启动 API

```bash
uvicorn app.main:app --host 0.0.0.0 --port 8432
```

健康检查：

```bash
curl -sS http://127.0.0.1:8432/api/system/health
```

产品、场地、证据和体验反馈接口使用 `/api/catalog` 前缀，体验方案、场次、领取、回执与恢复接口使用 `/api/pilots` 前缀，队列冻结、候选修订、签发与导出接口使用 `/api/cohorts` 前缀。

## 队列冻结流程

统计负责人用同一组条件在不同截止时点汇总时，迟到回执、证据审阅状态变化和产品目录更新不会影响已签发数字：

1. **冻结首版**：`POST /api/cohorts` 给出队列编码、截止时点（ISO 8601 含时区）和规则（产品、方案版本、场地类型/能力、类别、风险级别、项目、证据类型与份数、反馈数量、观察指标阈值等）。系统只采用截止时点前存在的场次和 append-only 观察版本，就地变化的产品/证据表通过内容快照固定截止时点的状态，并为每个候选场次逐条写入纳入或排除原因。
2. **候选修订**：`POST /api/cohorts/{code}/revisions` 指定更晚的新截止时点（规则可改可不改），生成 `proposed` 版本并返回相对上一版的 `added`/`removed`/`criteria_changes` 及每条变化的理由；同一队列同时只有一个候选版本。候选可放弃，放弃后版本号不前进。
3. **签发**：`POST /api/cohorts/{code}/versions/{v}/issue` 后版本成为 `frozen`。已签发版本、成员行和导出制品在服务层与 SQLite 触发器两层禁止改删，应用重启或恢复任务都不能使其悄然变化；产品后续停用、证据后续驳回均不改变历史版本保存的快照。
4. **验证与追溯**：`GET /api/cohorts/{code}/versions/{v}` 返回规则快照、计数和 `verification`（重算清单摘要与存档摘要核对）；成员明细保留 `session_id`、观察版本号与证据 `content_digest`，可回到原场次与证据材料，但不暴露场次提交人；事件流记录冻结、提出修订、签发、放弃与导出。
5. **去标识导出与重放**：`POST /api/cohorts/{code}/versions/{v}/exports` 生成 JSON 制品，成员按稳定顺序排列，移除提交人和联系人内容（参数中的手机号等会打码），附带规则摘要、清单摘要和内容摘要；同一幂等键的相同请求重放返回同一制品（含相同 `content_digest`），同一幂等键不同请求返回 409。

## API 与命令行冒烟

```bash
python -m app.cli smoke
python -m app.cli pilot-demo
python -m app.cli cohort-demo
```

`smoke` 在进程内检查根路径和健康接口。`pilot-demo` 会登记一个康复设备和体验场地，创建外骨骼步态体验方案，提交并领取场次，用于快速确认目录与试点运营链路。`cohort-demo` 会登记脑机产品、医院场地、方案、场次、观察回执和已接受证据，冻结 v1 队列并导出去标识制品。

## 目录结构

```text
app/
  catalog/          健康产品、试点场地、证据材料与公众反馈
  pilots/           体验方案、场次、租约、观察记录和人工干预
  cohorts/          队列冻结版本、成员清单、候选修订、签发与去标识导出
  api/              用户、角色、团队、认证、审计和系统接口
  core/             时钟、安全、隐私、异常与分页
  repositories/     身份、审计和团队数据访问
  services/         身份、后台任务、维护和通用服务
  cli.py            初始化、检查和冒烟入口
  database.py       SQLite 连接、事务、表结构与基础权限
tests/               核心、目录、试点运营和身份回归测试
tools/               数据库完整性检查
```

## 数据一致性

SQLite 连接启用外键、WAL、busy timeout 和同步写入策略。产品目录、证据审阅、反馈提交、场次领取、执行回执与人工干预使用即时事务；领取通过条件更新避免同一场次被重复分配。服务保存 UTC 时间字符串，测试可注入固定时钟验证退避、租约到期和跨日配额。审计记录会清理密码、令牌等敏感字段，体验反馈仅保存联系人摘要和是否允许后续联系。

队列冻结版本写入后不再更新：已签发版本、成员行、事件和导出制品由 SQLite 触发器在数据库层拒绝 UPDATE/DELETE，候选修订只能放弃重提；成员清单、规则快照和导出制品均保存规范化 JSON 的 SHA-256 摘要，任何版本都可重算摘要核对，导出参数中的联系人内容在冻结时即通过隐私清洗打码。
